How much memory would the matrix A \in R^{n×n} need for N = 2047 if it were
stored as a dense matrix (8 Byte per entry)? Compare with the memory of one
grid function and of the stencil.

For a dense matrix A a total of 8 bytes * 2047 * 2047 * 2047 * 2047 \approx 1.4046 \cdot 10^{14} bytes or approximately 140 TB of memory needed.

The grid function has a dimension of 2049 * 2049 and needs 8 bytes * 2049 * 2049 \approx 32 MB of memory.

The stencil has 3 * 3 elements and needs only 8 * 9 = 72 bytes. 
  
Hence, it is never a good idea to store such large matrices as dense matrices.

We parallelize the outermost loop using #pragma omp parallel for. 

The iterations are completely independent of each other since the stencil operation only reads from the array U and writes exclusively to disjoint, thread-specific elements of the array Y. 

No thread modifies data that another thread needs to read or write. 

So, the outer loop distribution provides enough work-sharing for the threads. 

How much faster is the program with -O3? What does the compiler do (see
lecture 3)

The program compiled with -O3 is approximately 40 times faster than its unoptimized counterpart.

Auto-Vectorization (SIMD): Guided by -march=native, the compiler leverages the specific hardware capabilities of the AMD Ryzen 7 5700X (such as AVX2). It packs multiple floating-point operations into a single vector register, executing up to four double precision additions and multiplications simultaneously in a single CPU instruction.

Loop Unrolling and Pipeline Scheduling: The compiler unrolls the innermost loops to reduce the branch overhead. It reorders assembly instructions to hide latencies and maximize instruction-level parallelism (ILP), ensuring that the CPU's execution pipelines remain filled.

Efficient Address Calculation: In the unoptimized -O0 version, every array access U[...] triggers a slow, explicit 2D-to-1D index calculation via multiplication in every iteration. The -O3 flag enables strength reduction, transforming these expensive index operations into fast, sequential pointer increments (pointer arithmetic).

Register Allocation: Instead of constantly pushing and pulling temporary variables (like sum) to and from the slow system stack in memory, the compiler pins these hot variables directly into the CPU's high-speed registers.

Compute the speedup Sp = T_1/T_p for N = 2047. Is the speedup ideal?
 
No. We would expect to double the execution speed by doubling the number of threads. Instead we observe values of 1.00, 1.39, 1.48, and 1.41 for 5-point stencil and 1.00, 1.41, 1.49, and 1.52 for the 9-point stencil (for 1, 2, 4, and 8 threads respectively). 

Explain your
observation (see lecture 3). 

The program is memory-bound. Once the fast L3 cache (32 MB) is full, the performance is limited by the bandwidth of the memory interface. At this point, the memory controller becomes a bottleneck. Consequently, using more than 4 cores results in no further runtime improvement, because the additional threads have to wait for data from the RAM.
